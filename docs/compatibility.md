# Compatibility boundary

Atlas keeps a small set of files only because something outside this repository, or an
older Atlas install, still addresses them by path. Each entry below names the consumer
that pins it and the condition under which removal can be considered. Check consumers,
packaging and migration coverage again before removing a surface.

| Surface | Pinned by | Remove when |
| --- | --- | --- |
| `Scripts\RunAsTI.cmd` (deny-only stub) | Shortcuts and context-menu commands written by Atlas 0.5.x and earlier | `playbook.conf` `UpgradableFrom` no longer admits any 0.5.x version |
| `Scripts\Install\Compat\Remove-AtlasLegacyElevationArtifacts.ps1` (PreInstall phase) | Registry commands, tasks and shortcuts left by Atlas 0.5.x elevation helpers | Same as above |
| `AtlasModules\Toolbox\**\*.cmd`, `*.reg` | The standalone Atlas Toolbox app invokes these by hard-coded path | The Toolbox app invokes `Scripts\Entry\Invoke-Toggle.ps1` by toggle name, or reads the generated `Toggles\catalog.json` |
| `Scripts\Registry\SecurityHealthTray\*.reg` byte-identical pairs with `Toolbox\Scripts\SecurityHealthTray\*.reg` | Same Toolbox path contract; `tests\Atlas.PayloadLayout.Tests.ps1` enforces the pairing | Same as above |
| `Scripts\Entry\Set-IndexConfiguration.cmd`, `Test-EdgeState.cmd`, `Test-Winget.cmd`, `Set-SettingsPageVisibilityLauncher.cmd` | Command-line entry points documented for support and used by the software picker and CBS update helper | Their PowerShell targets grow a documented, environment-sanitizing entry of their own |
| `AtlasModules\Flags\*.flag` after install completion | Machines installed before the state document existed; every Atlas reader now uses `C:\Windows\AtlasOS\state.json` and falls back to the flags only when it is absent | The oldest version `UpgradableFrom` admits wrote the state document |
| `HKLM\SOFTWARE\AtlasOS\Services` as the toggle write store, mirrored into `state.json` | The Toolbox app reads the registry tree | The Toolbox app reads the `toggles` section of `state.json` |

Rules for this boundary:

- Toggle records represent applied choices, with user work replayed at first sign-in.
  Default launcher labels do not seed the registry or state document. Legacy records
  remain supported because the store does not distinguish historical seeds from user choices.

- A compatibility surface is never the implementation. It forwards to, or is generated
  from, the one implementation under `Scripts\` or `Toggles\`. Toolbox launchers are
  generated by `tools\dev\New-ToggleLaunchers.ps1` from the toggle definitions exactly
  like the AtlasDesktop launchers.
- Each entry names its consumer and its removal condition here. Adding a surface without
  both is a review blocker.
- When `UpgradableFrom` changes, revisit every row that references the dropped version.
