# Languages in Atlas Manager

The app uses Fluent catalogs for interface text and Windows regional settings for
numbers and dates. This guide covers language selection, catalog maintenance and
the checks required before a translation ships.

## What the user gets

- **Match Windows** (the default): the app follows the Windows display-language
  list (Settings > Time & language > Language & region > Windows display
  language), in the user's order, and picks the first language it ships,
  preview translations included. While a preview translation is in use a
  one-line strip under the title bar says "<Language> is a preview
  translation." with two links, "Switch to English" (the English variant
  closest to the Windows list) and "Change language" (opens Settings), and a
  close button; closing it is remembered per language in `settings.json`. The list is re-read whenever the window is activated
  (including after a failed query at startup), so a change made in Settings
  shows up when the user comes back; Windows itself may need a sign-out
  before it reports some changes, and a query that fails while the app runs
  keeps the last working choice.
- **A manual language** in Settings > Language, kept in `settings.json` as a
  BCP 47 tag and applied at once. Switching redraws every page, including
  notices, check results and install results that are already on screen,
  without touching the current page, step, choices, focus, scroll position
  or a running install.
- **Regional formats are separate.** Numbers, file sizes, dates and times
  follow the Windows regional format (Settings > Regional format), including
  its customisations, whatever the app language is. An English UI with German
  number formats stays that way.
- **Graceful fallback.** A Windows language the app does not ship, a settings
  file naming a language this build lacks, or a failed Windows query all leave
  the app in English and say so on the Settings page. An unavailable choice is
  kept in the settings file, not rewritten.

**Source** identifies the English catalog and its regional overlay; it does not
claim native-speaker verification. **Preview** identifies translations awaiting
native-speaker review. Automated structural checks and selected rendered screens
cannot establish linguistic quality or coverage of every page.

Match Windows includes previews. The notice offers the English source language
and a link to language settings. Before marking a translation reviewed, record
who reviewed it, when, and which catalog revision they checked. Pay particular
attention to security choices, recovery advice and Windows Security labels.

Catalog completeness and variable usage are checked against the English source at
test time. No right-to-left language ships: see "Limitations".

## How it works

```
src/i18n/
  mod.rs        activation (override > setting > Windows list > English), the t! macro, the GPUI global
  catalog.rs    shipped locales (tag, native name, readiness, font fallbacks), embedded FTL, lookup chain
  negotiate.rs  CLDR-aware matching (fluent-langneg, likely subtags), regional overlay policy
  describe.rs   words for semantic state: check results, outcomes, notices, option screens, playbook text
  fmt.rs        regional numbers, dates and times through Windows NLS
  pseudo.rs     the qps-ploc transform
  checks.rs     release gates (tests): catalogs, t! call sites, plurals
i18n/<tag>/atlas.ftl   one Fluent catalog per language, compiled into the executable
src/services/locale.rs Win32 adapter: GetUserPreferredUILanguages, GetUserDefaultLocaleName,
                       GetNumberFormatEx, GetDateFormatEx, GetTimeFormatEx, GetLocaleInfoEx
```

**Messages, not strings.** Services and the model never store display text.
A system check yields a `CheckDetail` value, an install ends in an
`InstallOutcome` plus the `Phase` it reached, a startup problem is a
`Notice` variant with the raw error inside; `describe.rs` turns those into
sentences when a page renders. That is what lets a language switch re-word a
failure that happened ten minutes ago. Raw diagnostics (Windows error text,
paths, versions, build numbers, the installer's log lines and its command
line) are passed through as text arguments and never translated or
reformatted; identifiers such as build numbers are passed as text so they
are never grouped like quantities.

**Lookup chain.** A `Catalog` is an ordered list of Fluent bundles, first
choice first, English source last. A message missing from a translation
falls through to the next language; a translation that fails to format (a
broken reference, a cycle, a variable it does not receive) is skipped for
that message and logged once. The gate in `checks.rs` formats every catalog
*on its own*, with no fallback, and checks message references and
per-branch text variables statically on the syntax tree (so an unsampled
branch cannot hide a bad reference or a dropped value); these checks catch structural errors before release. If
every language still fails for a message, the sentence is shown with the
unresolved parts elided (never Fluent's `{...}` syntax), an error is logged,
and debug builds panic. That last path is a safety net for a caller passing
the wrong arguments, not a promise that an elided sentence is still useful.
The source is complete by construction: the gate lexes every Rust source
file, finds each `t!` invocation whatever its path or delimiter, parses its
arguments with Rust's own grammar (`syn`), and checks them against `en-GB`
for existence and exact argument names; it fails if a source message is
unused. Playbook message ids are checked against an inventory built from
the built-in manifest.

**Negotiation.** `fluent-langneg` with the CLDR `likelysubtags` data and the
Matching strategy, one requested tag at a time so the Windows order is kept.
`zh-TW`, `zh-HK` and `zh-MO` resolve to `zh-Hant`; `zh-CN`, `zh-SG` and bare
`zh` to `zh-Hans`; scripts are never crossed, and a Traditional Chinese user
with English second never sees Simplified. Regional requests take the shipped
variant of their language (`pt-PT` gets `pt-BR`, `fr-CA` gets `fr`). Two
rules sit on top of the library: English regions with British spelling
(`en-AU`, `en-IE`, `en-IN`, ...) prefer `en-GB` as Windows does, and a
regional overlay is always followed by its base (`en-US` then `en-GB`) so a
message missing from the overlay never comes from a later language in the
Windows list. The `qps-ploc` pseudo-locale is never chosen automatically.

**Plurals and numbers.** Counts are passed as numbers, so Fluent selectors
see them (`[one]`, `[few]`, `[many]`, `[other]`, or exact `[1]`/`[2]`) with
each language's CLDR rules. Every bundle carries a formatter that renders
numeric placeables through the Windows regional format, so `{ $count }` in
any language shows grouping and digits as the user's region has them. Sizes
in MB and clock times are formatted the same way. Dates use a Windows
pattern verbatim, never an edited one: the user's own long date when it has
no weekday (so customisations survive), otherwise the first weekday-free
long date Windows lists for the locale through `EnumDateFormatsExEx`,
otherwise the user's long date unchanged ("21 October 2025", "October 21,
2025", "21. Oktober 2025", "2025. október 21.", "2025年10月21日", Thai
Buddhist years included). `ATLAS_FORMAT_LOCALE=<tag>` overrides the regional
format for review; a change to the regional format while the app runs is
picked up on the next activation.

**Fonts.** DirectWrite picks CJK fallback fonts by the *regional* locale, so
on a Latin-region machine Traditional Chinese would otherwise be drawn with
Simplified-style glyphs. Each locale can name font families to try first
(`font_fallbacks` in `catalog.rs`); the shell applies them at the root and
every element inherits them.

**Playbook text.** The package's own option labels and page descriptions are
English text from `playbook.conf`. The catalog has a translation for each
option this app knows (`playbook-option-<name>`), used only when the
package's text exactly matches the baseline in `i18n/playbook-source.ftl`.
This baseline is separate from the English UI catalog, so copy can be
rewritten without breaking package recognition. The catalog gate checks
the baseline against the built-in manifest. Option explanations use the
same guard as labels and appear before selection. A
future package that rewords an option shows its own words; an option the app
has never seen shows its own words. Option *names* (`defender-enable`) are
never translated and are what the installer receives.

See [writing guidance](writing.md) and [translation guidance](translating.md) for
copy conventions and unresolved terminology.

**The restart notice.** After a successful unattended install the front
door restarts Windows and passes a notice to `shutdown.exe /c`. The app now
captures that notice in its own language when the install starts
(`InstallRequest.restart_comment`) and passes it as `-RestartComment`, a new
optional parameter of `Install-Atlas.ps1` that strips control characters
and applies the 512-character limit before binding it as data; without it
the script keeps its English default. The app passes the parameter only to
a front door whose own `param(...)` block declares it (read with a small
quote- and comment-aware parser, case-insensitively; a mention in a comment
or default value does not count), so packages built before it existed are
called exactly as before. Older session records without the field reattach
unchanged.

**What stays as it is.** `settings.json` (`language` is a new optional
field; older files read as Match Windows), `session.json` (`restart_comment`
is optional), `launcher.json`, `state.json`, the install log, the PowerShell
command line's other arguments, exit codes, the front door's English
progress lines (the phase parser reads them), release notes from GitHub
(shown in the language they were written in) and URLs.

## Review and test hooks

```
AtlasManager.exe --language de                        # outranks the setting; any shipped tag, or qps-ploc
ATLAS_LANGUAGE=zh-TW atlas                 # same, from the environment
ATLAS_FORMAT_LOCALE=de-DE atlas            # regional format for numbers, dates and times
ATLAS_WINDOWS_LANGUAGES=de-DE,en-US atlas  # stands in for the Windows display-language list; "error" simulates a failed query
cargo test --bin AtlasManager i18n                # negotiation, catalogs, plurals, formatting, describe, mutation gates
cargo run --example i18n_spike             # the GPUI rendering probe for RTL, CJK and mixed scripts
```

`tools\Get-AccessibilityTree.ps1` prints what UI Automation (and Narrator)
sees; accessible names come from the same catalog as the visible text.
`tools\Get-AccessibilityTree.ps1 -Invoke 日本語` switches language through
the accessible action, as voice control would, and works whether or not the
control is scrolled into view: every clickable control registers the
accessibility Click action itself instead of relying on GPUI's synthesised
mouse click at the control's centre.

## Adding a language

1. Copy `i18n/en-GB/atlas.ftl` to `i18n/<tag>/atlas.ftl` and translate every
   message. Keep every `{ $variable }`; reorder freely. Use your language's
   CLDR plural categories in selectors. Read the comments: values marked
   "text" are inserted verbatim. Match Microsoft's Windows terminology for
   Windows features, especially the four Virus & threat protection switches.
2. Add a `Locale` entry to `LOCALES` in `src/i18n/catalog.rs`: tag, the
   language's own name for itself (shown in Settings, no flags), English
   name, direction, `Readiness::Preview`, font fallbacks if the script needs
   them, and `include_str!` of the file. Keep the source first; order breaks
   negotiation ties.
3. Run `cargo test --bin AtlasManager catalog_checks`. It rejects syntax errors,
   duplicate or unknown ids, missing messages, variables the source does not
   have, plural categories the language does not have, and messages that
   fail to format. Add a negotiation case in `negotiate.rs` if the tag has
   regional or script variants worth pinning down.
4. Launch every page in the language using `--language <tag>`, `--page`, `--step`
   and a harmless installer fixture. Check long strings at the minimum window size
   (700 x 520). Check the pseudo-locale still fits if you changed
   layout.
5. Ship as Preview. Change readiness only after a native speaker has reviewed
   the catalog, and record who and when in the pull request.

A right-to-left language additionally needs GPUI to shape and order RTL text
(see below) and a mirrored layout; do not add one until that is in place.

## Limitations

- **Translations are AI-assisted.** Non-English catalogs remain previews. No native-speaker review is evidenced in this repository. Structural tests and visual spot checks do not prove natural wording.
- **Right-to-left scripts cannot be rendered by the pinned GPUI.** The
  rendering probe (`examples/i18n_spike.rs`)
  showed Arabic and Hebrew drawn in logical order with unshaped, isolated
  letterforms, with or without RLI/PDI isolates; DirectWrite's layout is
  created but its bidi and shaping results are not what reaches the screen
  in this build. Arabic, Hebrew, Persian and Urdu are therefore not shipped
  and would be excluded from the language list by their `Direction` even if
  a catalog existed. Fluent's FSI/PDI isolation of placeables is switched
  off for the same reason (it only leaked into accessible names). Both
  should be turned back on with the first RTL locale, together with a
  mirrored layout, once GPUI renders it.
- **Windows language and regional-format changes are followed on
  activation, not instantly.** There is no WM_SETTINGCHANGE bridge in the
  pinned GPUI; both are re-read when the window becomes active. Tests use
  `ATLAS_WINDOWS_LANGUAGES` to exercise recovery paths; release validation must
  also cover changes to the Windows display language.
- **Narrator requires release validation.** UI Automation checks do not verify
  speech output or voice selection for a non-English language. AccessKit in this GPUI exposes no
  per-node language property, so Narrator chooses its voice by its own
  rules.
- **Thai and Hindi wrapping** uses a local GPUI patch with ICU dictionary
  line breaks and grapheme boundaries. See
  [patch maintenance](../vendor/gpui-pre/ATLAS-PATCH.md). Other dictionary-broken
  scripts have not been verified.
- **Release notes** from GitHub stay in the language they were written in.
- **Elevation across users.** The elevated relaunch reads the same
  `settings.json` and the same Windows display-language list as the
  launching user in the common case; running the elevated copy as a
  different account with different language settings was not tested.
