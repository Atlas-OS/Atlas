# Languages in Atlas Manager

Atlas Manager takes its interface text from Fluent catalogs, and formats numbers and dates with the Windows regional settings.
This page is for contributors who maintain catalogs, add languages or review translations.
[Writing for Atlas](writing.md) sets the copy conventions, and [translation guidance](translating.md) records each language's terms and open questions.

## What the user gets

- **Match Windows**, the default.
  The app uses the first of its languages, previews included, that appears in the Windows display-language list (**Settings** > **Time & language** > **Language & region** > **Windows display language**).
  - The app reads the list again whenever the window is activated, including after a query that failed at startup.
  - Windows may need a sign-out before it reports some changes.
  - A query that fails while the app runs keeps the last working choice.
- **A manual language**, chosen in **Settings** > **Language** and saved in `settings.json` as a BCP 47 tag.
  - The control is a combo box that lists each language by its native name.
    Previews carry a **Preview** chip, and **Match Windows** shows the language it gives, as in "Match Windows (English (United Kingdom))".
  - The arrow keys only move the highlight, and a choice applies when you commit it with Enter, Space or a click.
  - Every page then redraws, including notices, check results and install results already on screen.
    The page, step, choices, focus, scroll position and any running install stay as they were.
- **A preview notice.** While a preview translation is in use, an informational bar at the top of the page reads "`<Language>` is a preview translation and may contain mistakes."
  - **Switch to English** saves the English variant closest to the Windows list as the language choice, or `en-GB` if none is close.
  - **Change language** opens Settings.
    It's hidden on Settings, and while updates, an install or a media job is running.
  - Closing the bar is remembered per language in `settings.json`.
  - With other bars shown above every page, the notice takes at most 40% of the window's height and scrolls beyond that, so large text never squeezes the page out.
- **Separate regional formats.** Numbers, file sizes, dates and times follow the Windows regional format (**Settings** > **Regional format**), customisations included, whatever the app language.
  An English interface with German number formats stays that way.
  The app can't draw right-to-left text, so a date or time that the format writes in such a script shows as `2025-10-21` or `20:13`, and Settings names the format in English, with a note ([limitations](#limitations)).
- **Fallback to English**, noted in Settings, when Windows asks for a language the app doesn't include, `settings.json` names one this build lacks, or the Windows query fails.
  The app keeps an unavailable choice in the settings file, and doesn't rewrite it.

**Source** is the English catalog and its overlay; it claims no native-speaker verification.

No right-to-left language is included ([limitations](#limitations)).

## Checking a language

[Review tools](review-tools.md) lists the flags and variables that choose a language (`--language`, `ATLAS_LANGUAGE`, `ATLAS_FORMAT_LOCALE` and `ATLAS_WINDOWS_LANGUAGES`), the preview states and the language test commands.
`tools\Get-AccessibilityTree.ps1` prints what UI Automation and Narrator see; accessible names come from the same catalog as visible text.

## Adding a language

1. Copy `i18n/en-GB/atlas.ftl` to `i18n/<tag>/atlas.ftl` and translate every message.
   - Keep every `{ $variable }`, and reorder them freely.
   - Use your language's CLDR plural categories.
   - Insert values commented as "text" as they are.
   - Use Microsoft's Windows terminology, especially for the four Windows Security protection switches and the [features Atlas turns off](translating.md#windows-feature-names).
   - Record your term for the Atlas package and your step names in [translation guidance](translating.md).
2. Add a `Locale` to `LOCALES` in `src/i18n/catalog.rs`: the tag, the native name (shown in Settings, without flags), the English name, the direction, `Readiness::Preview`, font fallbacks if the script needs them, `include_str!` of the file and `pseudo: false`.
   Keep the source first, because the order breaks negotiation ties.
3. Run `cargo test --bin AtlasManager catalog_checks`.
   It rejects syntax errors, duplicate or unknown ids, missing messages, variables the source lacks, plural categories the language lacks, messages that fail to format, and more than 40 messages identical to English.
   Add a case to `negotiate.rs` if the tag has regional or script variants worth pinning.
4. Open every page with `--language <tag>`, `--page`, `--step` and a harmless installer fixture.
   The debug build's [preview states](review-tools.md#preview-states) reach states such as failed updates, unreadable switches and report errors.
   Check long strings at the minimum window size of 700 × 520, and if you changed the layout, check that the pseudo-locale still fits.
5. Release it as a preview, and change its readiness only after [native-speaker review](#translation-review).

Don't add a right-to-left language until GPUI shapes and orders right-to-left text and the layout is mirrored ([limitations](#limitations)).

## Translation review

Non-English catalogs stay previews until a native speaker reviews them.

- Follow the [locale conventions and open terminology questions](translating.md).
- Focus on security choices, recovery advice and Windows Security labels.
- Check long explanations at the minimum 700 × 520 window size.
- Check accessible names as well as visible labels.
- Record in the pull request who reviewed the catalog, when, and which revision of it.

## Package text

Option labels and page descriptions come in English from the Atlas package's `playbook.conf`.

- The app translates known options (`playbook-option-<name>`), their explanations (shown before selection) and known page descriptions only when the package text exactly matches `i18n/playbook-source.ftl`.
- Unknown or reworded options show the package's own words, without an explanation written for the app that might not fit them.
- Option names, such as `defender-enable`, are never translated; the installer receives them.
- The baseline is separate from the interface catalog, so interface copy can change without breaking recognition, and the catalog gate checks the baseline against the built-in manifest.

To change how an option reads in the app, edit its label or description in `i18n/en-GB/atlas.ftl`.
Don't edit `i18n/playbook-source.ftl` to change interface wording: it records the exact package text the app recognises.
When the package itself changes an option, review the option's implementation and every affected translation before updating the baseline.
Option identifiers, defaults and the installer command don't depend on interface copy.

## How it works

| Path | Role |
| --- | --- |
| `src/i18n/mod.rs` | Activation (override, then setting, then Windows list, then English), the `t!` macro and the GPUI global. |
| `src/i18n/catalog.rs` | The available locales (tag, native name, readiness and font fallbacks), embedded FTL and the lookup chain. |
| `src/i18n/negotiate.rs` | CLDR-aware matching (`fluent-langneg` with likely subtags) and the regional overlay policy. |
| `src/i18n/describe.rs` | Words for semantic state: check results, outcomes, notices, protection reminders, option screens, package text and lists. |
| `src/i18n/fmt.rs` | Regional numbers, dates and times through Windows NLS. |
| `src/i18n/pseudo.rs` | The `qps-ploc` transform. |
| `src/i18n/checks.rs` | The release gates, run as tests: catalogs, `t!` call sites and plurals. |
| `src/i18n/line_breaks.rs` | Tests that a mark after a no-break space, and closing punctuation, wrap with the word before them. |
| `i18n/<tag>/atlas.ftl` | One Fluent catalog per language, compiled into the executable. |
| `i18n/playbook-source.ftl` | The exact package wording the app recognises ([package text](#package-text)). |
| `src/services/locale.rs` | The Win32 adapter: `GetUserPreferredUILanguages`, `GetUserDefaultLocaleName`, `GetNumberFormatEx`, `GetDateFormatEx`, `GetTimeFormatEx`, `GetLocaleInfoEx` and `EnumDateFormatsExEx`. |

- **Messages, not strings.** Services and the model store values, never display text: a `CheckDetail` per system check, an `InstallOutcome` with the `Phase` reached, and a startup `Notice` holding the raw error.
  `describe.rs` words them at render time, so a language switch re-words a failure from ten minutes ago.
  Raw diagnostics (Windows error text, paths, versions, build numbers, installer log lines and the command line) pass through as text arguments, never translated or reformatted.
  Identifiers such as build numbers go as text, so they're never grouped like quantities.
- **Lookup chain.** A `Catalog` is an ordered list of Fluent bundles, first choice first and the English source last.
  A missing message falls through to the next language.
  A translation that fails to format (a broken reference, a cycle or a missing variable) is skipped for that message and logged once.
  If every language fails, a safety net for wrong caller arguments shows the sentence with unresolved parts left out, never Fluent's `{...}`, logs an error, and panics in debug builds.
  The shortened sentence may not be useful.
- **Release gate.** `checks.rs` lists every check in its module header.
  It formats each catalog alone, with no fallback, and checks references and per-branch text variables statically, so a branch the gate doesn't sample can't hide an error.
  Every `t!` call, parsed with `syn`, must match an `en-GB` message and its exact argument names, every source message must be used, and the `playbook-*` message ids must match the built-in manifest.
- **Negotiation.** `fluent-langneg` matches with CLDR likely subtags (the Matching strategy), one requested tag at a time to keep the Windows order.
  Scripts are never crossed: `zh-TW`, `zh-HK` and `zh-MO` get `zh-Hant`, `zh-CN`, `zh-SG` and `zh` get `zh-Hans`, and Traditional Chinese with English second never yields Simplified.
  Regional requests take the available variant, so `pt-PT` gets `pt-BR` and `fr-CA` gets `fr`.
  Atlas adds two rules on top of the library:
  - English regions with British spelling (`en-AU`, `en-IE`, `en-IN` and others) prefer `en-GB`, as Windows does.
  - An overlay is always followed by its base (`en-US`, then `en-GB`), so its gaps never fill from a later Windows language.

  `qps-ploc` is never chosen automatically.
- **Plurals and numbers.** Counts arrive as numbers, so selectors (`[one]`, `[few]`, `[many]`, `[other]` and exact `[1]` or `[2]`) follow each language's CLDR rules.
  Every bundle formats numeric placeables through the Windows regional format, so `{ $count }` shows the region's grouping and digits in any language, and sizes and clock times do the same.
  Dates use an unedited Windows long-date pattern, without a weekday where Windows offers one, and keep the user's customisations where possible (`date_pattern` in `src/services/locale.rs`).
  Thai Buddhist years are included.
- **Lists.** `join_and` in `describe.rs` joins a list with `list-separator`, and its last two items with `list-and`, so `$a` may already hold several items: "Tamper Protection, Real-time protection and Cloud-delivered protection".
  The protection reminders and the close confirmation name switches this way.
  Chinese and Japanese join with 、 or 和 and no spaces.
- **Fonts.** DirectWrite picks CJK fallback fonts by the regional locale, so a PC with a Latin-script region would draw Traditional Chinese with Simplified-style glyphs.
  Each locale can name families to try first (`font_fallbacks` in `catalog.rs`), which `theme::text_font` carries.
  Both roots set it, the window's root and the content dialog's layer, because a prompt is drawn as a separate root, so every element inherits the families.
- **Dialogs.** Every prompt the window makes, such as a close confirmation, is a ContentDialog drawn in the window (`src/ui/content_dialog.rs`), so its title, message and buttons come from the catalog.
- **Restart notice.** Atlas Manager restarts Windows itself with `shutdown.exe /r /t 0 /c`, when the countdown after a successful install ends or when you choose **Restart now**.
  The notice is `shutdown-comment` (`prepare-shutdown-comment` during preparation), in the language on screen at that moment, cut to the 512 characters `shutdown.exe` accepts.
  The app never passes `-Restart` or `-RestartComment` to the front door, so the front door never schedules its own restart.
  When you run the front door directly for testing, `Install-Atlas.ps1 -Restart -RestartComment <text>` sets the notice, with control characters stripped and a 512-character cap; without a comment, the notice is English.
- **Not translated.** Stored files and machine interfaces stay language-neutral:
  - `settings.json`, where `language` is `system` or a tag, and a missing value means Match Windows;
  - `session.json`, where records without `restartComment` still load;
  - `launcher.json`, `state.json`, the install log, the PowerShell command line and exit codes;
  - the front door's English progress lines, which the phase parser reads, and URLs.

## Limitations

- **Translations are AI-assisted.** Non-English catalogs stay previews until a native speaker reviews them.
  Structural tests and spot checks don't prove natural wording.
- **The pinned GPUI can't render right-to-left scripts.** The probe (`examples/i18n_spike.rs`) draws Arabic and Hebrew in logical order with unshaped, isolated letterforms, with or without RLI and PDI isolates.
  DirectWrite builds the layout, but its bidi and shaping results never reach the screen.
  - Arabic, Hebrew, Persian and Urdu aren't included, and their `Direction` would leave them out of the language list even with a catalog.
  - Fluent's FSI and PDI isolation of placeables is off, because with only left-to-right languages the marks would reach only accessible names and copied text.
  - Right-to-left regional formats are common with an English interface, so `src/i18n/fmt.rs` falls back to numeric dates and times wherever Windows would use a right-to-left script.
  - Once GPUI renders right-to-left text, the first right-to-left locale needs three changes: turn isolation back on, remove that fallback and mirror the layout.
- **Windows changes apply on activation.** The pinned GPUI has no `WM_SETTINGCHANGE` bridge, so the app reads the display-language list and regional format again when the window becomes active.
  Tests use `ATLAS_WINDOWS_LANGUAGES` for recovery paths, and a release check also changes the real Windows display language.
- **Narrator's voice isn't checked automatically.** The window reports the app's language as every node's UI Automation culture, and each language in **Settings** > **Language** reports its own ([accessibility](accessibility.md)).
  UI Automation checks don't show that Narrator speaks a non-English language with the matching voice, so a release check listens with Narrator.
- **Thai and Hindi wrapping relies on a vendored GPUI change** for ICU dictionary line breaks and grapheme boundaries ([GPUI changes](../vendor/gpui-pre/ATLAS-PATCH.md)).
  Other scripts that break by dictionary are unverified.
  A related change keeps the German closing quote `“` and CJK closing and stop punctuation (`。`, `、`, `）` and `」`) from starting a row.
- **Release notes** from GitHub stay in the language they were written in.
- **Elevation reads the elevated account's settings.** The elevated copy reads `settings.json` and the display-language list of the account it runs as.
  When UAC elevates with a different administrator account, that account's language settings apply.
