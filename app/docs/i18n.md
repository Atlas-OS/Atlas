# Languages in Atlas Manager

Atlas Manager takes interface text from Fluent catalogs and formats numbers and
dates with the Windows regional settings. This guide is for contributors who
maintain catalogs, add languages or review translations. Copy conventions are
in [writing guidance](writing.md); open terminology is in
[translation guidance](translating.md).

## What the user gets

- **Match Windows** (default). The app uses the first of its languages,
  previews included, that appears in the Windows display-language list
  (Settings > Time & language > Language & region > Windows display language).
  - The list is re-read whenever the window is activated, including after a
    failed query at startup.
  - Windows may need a sign-out before it reports some changes.
  - A query that fails while the app runs keeps the last working choice.
- **A manual language** (Settings > Language), saved in `settings.json` as a
  BCP 47 tag. The control is a combo box: each language is listed by its
  native name, previews carry a "Preview" chip, and Match Windows shows the
  language it gives, as in "Match Windows (English (United Kingdom))". The
  arrow keys only move the highlight; a choice applies when it's committed
  with Enter, Space or a click. Every page then redraws, including notices,
  check results and install results already on screen. Page, step, choices,
  focus, scroll position and any running install are untouched.
- **A preview notice.** While any preview translation is in use, an
  informational bar at the top of the page reads "<Language> is a preview
  translation and may contain mistakes."
  - "Switch to English" saves the English variant closest to the Windows list
    (otherwise `en-GB`) as the language choice.
  - "Change language" opens Settings; it is hidden on Settings and while
    updates, an install or a media job is running.
  - Closing the bar is remembered per language in `settings.json`.
  - With any other bar shown above every page, it takes at most 40% of the
    window's height and scrolls beyond that, so large text never squeezes the
    page out.
- **Separate regional formats.** Numbers, file sizes, dates and times follow
  the Windows regional format (Settings > Regional format), customisations
  included, whatever the app language. An English UI with German number
  formats stays that way. Exception: the app cannot draw right-to-left text, so
  a date or time the format writes in such a script shows as `2025-10-21` or
  `20:13`, and the format is named in English, with a note in Settings (see
  [Limitations](#limitations)).
- **Fallback to English**, noted in Settings, when Windows asks for a language
  the app does not include, `settings.json` names one this build lacks, or the
  Windows query fails. An unavailable choice is kept in the settings file, not
  rewritten.

**Source** is the English catalog and its overlay; it claims no native-speaker
verification. **Preview** awaits native-speaker review; only that review moves a
translation out of Preview ([Adding a language](#adding-a-language), step 5).
Automated checks and spot-checked screens cannot prove linguistic quality or
cover every page. No right-to-left language is included (see
[Limitations](#limitations)).

## Review and test hooks

| Hook | Effect |
|---|---|
| `--language <tag>` | Overrides the setting. The tag of any available language, or `qps-ploc`. |
| `ATLAS_LANGUAGE=<tag>` | Same, from the environment. |
| `ATLAS_FORMAT_LOCALE=<tag>` | Regional format for numbers, dates and times. |
| `ATLAS_WINDOWS_LANGUAGES=<tag>,<tag>` | Stands in for the Windows display-language list; `error` simulates a failed query. |

Variables last for the PowerShell session; clear each with
`Remove-Item Env:ATLAS_LANGUAGE` (and so on).

```powershell
.\AtlasManager.exe --language de
$env:ATLAS_LANGUAGE = 'zh-TW'; .\AtlasManager.exe
cargo test --bin AtlasManager i18n    # negotiation, catalogs, plurals, formatting, describe, and that the gate rejects broken catalogs
cargo run --example i18n_spike        # GPUI rendering probe for RTL, CJK and mixed scripts
```

`tools\Get-AccessibilityTree.ps1` prints what UI Automation and Narrator see;
accessible names come from the same catalog as visible text.
`tools\Get-AccessibilityTree.ps1 -Invoke 日本語` switches language through the
accessible action, as voice control would. It works on controls scrolled out of
view: each clickable control registers its own accessibility Click action
rather than relying on GPUI's synthesised centre click.

## Adding a language

1. Copy `i18n/en-GB/atlas.ftl` to `i18n/<tag>/atlas.ftl` and translate every
   message. Keep every `{ $variable }`; reorder freely. Use your language's CLDR
   plural categories. Values commented as "text" are inserted verbatim. Use
   Microsoft's Windows terminology, especially for the four Virus & threat
   protection switches and the [features Atlas turns
   off](translating.md#windows-feature-names). Record your term for the Atlas
   package and your step names in [translation guidance](translating.md).
2. Add a `Locale` to `LOCALES` in `src/i18n/catalog.rs`: tag, native name
   (shown in Settings; no flags), English name, direction, `Readiness::Preview`,
   font fallbacks if the script needs them, `include_str!` of the file and
   `pseudo: false`. Keep the source first; order breaks negotiation ties.
3. Run `cargo test --bin AtlasManager catalog_checks`. It rejects syntax
   errors, duplicate or unknown ids, missing messages, variables the source
   lacks, plural categories the language lacks, messages that fail to format,
   and more than 40 messages identical to English. Add a case to
   `negotiate.rs` if the tag has regional or script variants worth pinning.
4. Open every page with `--language <tag>`, `--page`, `--step` and a harmless
   installer fixture; the debug builds'
   [review previews](../README.md#review-flags-and-variables) reach states
   such as failed updates, unreadable switches and report errors. Check long
   strings at the minimum window size (700 x 520). If you changed layout,
   check the pseudo-locale still fits.
5. Release it as Preview. Change readiness only after native-speaker review, and
   record in the pull request who reviewed it, when, and which catalog
   revision. Reviewers should focus on security choices, recovery advice and
   Windows Security labels.

Do not add a right-to-left language until GPUI shapes and orders RTL text and
the layout is mirrored (see [Limitations](#limitations)).

## How it works

| Path | Role |
|---|---|
| `src/i18n/mod.rs` | Activation (override > setting > Windows list > English), the `t!` macro, the GPUI global |
| `src/i18n/catalog.rs` | Available locales (tag, native name, readiness, font fallbacks), embedded FTL, lookup chain |
| `src/i18n/negotiate.rs` | CLDR-aware matching (`fluent-langneg`, likely subtags), regional overlay policy |
| `src/i18n/describe.rs` | Words for semantic state: check results, outcomes, notices, protection reminders, option screens, package text, lists |
| `src/i18n/fmt.rs` | Regional numbers, dates and times through Windows NLS |
| `src/i18n/pseudo.rs` | The `qps-ploc` transform |
| `src/i18n/checks.rs` | Release gates (tests): catalogs, `t!` call sites, plurals |
| `src/i18n/line_breaks.rs` | Tests that a mark after a no-break space, and closing punctuation, wrap with the word before them (vendored GPUI patch) |
| `i18n/<tag>/atlas.ftl` | One Fluent catalog per language, compiled into the executable |
| `i18n/playbook-source.ftl` | The exact package wording the app recognises (see "Package text") |
| `src/services/locale.rs` | Win32 adapter: `GetUserPreferredUILanguages`, `GetUserDefaultLocaleName`, `GetNumberFormatEx`, `GetDateFormatEx`, `GetTimeFormatEx`, `GetLocaleInfoEx`, `EnumDateFormatsExEx` |

- **Messages, not strings.** Services and the model store values, never
  display text: a `CheckDetail` per system check, an `InstallOutcome` with the
  `Phase` reached, a startup `Notice` holding the raw error. `describe.rs`
  words them at render time, so a language switch re-words a failure from ten
  minutes ago. Raw diagnostics (Windows error text, paths, versions, build
  numbers, installer log lines and command line) pass through as text
  arguments, never translated or reformatted. Identifiers such as build numbers
  go as text so they are never grouped like quantities.
- **Lookup chain.** A `Catalog` is an ordered list of Fluent bundles, first
  choice first, English source last. A missing message falls through to the
  next language. A translation that fails to format (broken reference, cycle,
  missing variable) is skipped for that message and logged once. If every
  language fails, a safety net for wrong caller arguments shows the sentence
  with unresolved parts elided (never Fluent's `{...}`), logs an error, and
  panics in debug builds. The elided sentence may not be useful.
- **Release gate.** `checks.rs` lists every check in its module header. It
  formats each catalog alone, with no fallback, and checks references and
  per-branch text variables statically, so an unsampled branch cannot hide an
  error. Every `t!` call (parsed with `syn`) must match an `en-GB` message and
  its exact argument names, every source message must be used, and the
  `playbook-*` message ids must match the built-in manifest.
- **Negotiation.** `fluent-langneg` with CLDR likely subtags (Matching
  strategy), one requested tag at a time to keep the Windows order. Scripts are
  never crossed: `zh-TW`, `zh-HK`, `zh-MO` get `zh-Hant`; `zh-CN`, `zh-SG`,
  `zh` get `zh-Hans`; Traditional Chinese with English second never yields
  Simplified. Regional requests take the available variant (`pt-PT` gets
  `pt-BR`, `fr-CA` gets `fr`). Atlas adds two rules on top of the library:
  British-spelling English regions (`en-AU`, `en-IE`, `en-IN`, ...) prefer
  `en-GB`, as Windows does, and an overlay is always followed by its base
  (`en-US` then `en-GB`), so its gaps never fill from a later Windows language.
  `qps-ploc` is never chosen automatically.
- **Plurals and numbers.** Counts are passed as numbers, so selectors (`[one]`,
  `[few]`, `[many]`, `[other]`, exact `[1]`/`[2]`) follow each language's CLDR
  rules. Every bundle formats numeric placeables through the Windows regional
  format, so `{ $count }` shows the region's grouping and digits in any
  language; MB sizes and clock times do the same. Dates use an unedited
  Windows long-date pattern, without a weekday where Windows offers one and
  keeping the user's customisations where possible (`date_pattern` in
  `src/services/locale.rs`). Thai Buddhist years are included.
- **Lists.** `join_and` in `describe.rs` joins a list with `list-separator`
  and its last two items with `list-and`, so `$a` may already hold several
  items: "Tamper Protection, Real-time protection and Cloud-delivered
  protection". The protection reminders and the close confirmation name
  switches this way. Chinese and Japanese join with 、 or 和 and no spaces.
- **Fonts.** DirectWrite picks CJK fallback fonts by the *regional* locale, so
  a Latin-region machine would draw Traditional Chinese with Simplified-style
  glyphs. Each locale can name families to try first (`font_fallbacks` in
  `catalog.rs`); the shell sets them at the root for every element to inherit.
- **Package text.** Option labels and page descriptions come in English from
  the package's `playbook.conf`. Known options (`playbook-option-<name>`),
  their explanations (shown before selection) and known page descriptions are
  translated only when the package text exactly matches
  `i18n/playbook-source.ftl`. Unknown or reworded options show the package's
  words and no explanation. The baseline is separate from the UI catalog, so
  interface copy can change without breaking recognition; the gate checks it
  against the built-in manifest. Option *names* (`defender-enable`) are never
  translated; the installer receives them.
- **Dialogs.** Every prompt the window makes, such as a close confirmation, is
  a ContentDialog drawn in the window (`src/ui/content_dialog.rs`), so its
  title, message and buttons come from the catalog. The legacy task dialog it
  replaces had an English "Warning" caption.
- **Restart notice.** Atlas Manager restarts Windows itself with
  `shutdown.exe /r /t 0 /c`, when the countdown after a successful install
  ends or on "Restart now". The notice is `shutdown-comment`
  (`prepare-shutdown-comment` during preparation) in the language on screen at
  that moment, cut to the 512 characters `shutdown.exe` accepts. The app never
  passes `-Restart` or `-RestartComment` to the front door, so the front door
  never schedules its own restart. Command-line installs can use
  `Install-Atlas.ps1 -Restart -RestartComment <text>` (control characters
  stripped, 512-character cap); without it the notice is English.
- **Not translated.** Stored files and machine interfaces stay
  language-neutral: `settings.json` (`language` is `system` or a tag;
  missing means Match Windows), `session.json` (records without
  `restartComment` still load), `launcher.json`, `state.json`, the install
  log, the PowerShell command line, exit codes, the front door's English
  progress lines (the phase parser reads them) and URLs.

## Limitations

- **Translations are AI-assisted.** Non-English catalogs stay Preview until a
  native speaker reviews them; structural tests and spot checks do not prove
  natural wording.
- **The pinned GPUI cannot render right-to-left scripts.** The probe
  (`examples/i18n_spike.rs`) draws Arabic and Hebrew in logical order with
  unshaped, isolated letterforms, with or without RLI/PDI isolates.
  DirectWrite builds the layout, but its bidi and shaping results never reach
  the screen.
  - Arabic, Hebrew, Persian and Urdu are not included. Their `Direction` would
    exclude them from the language list even with a catalog.
  - Fluent's FSI/PDI isolation of placeables is off: with only left-to-right
    languages, the marks would only reach accessible names and copied text.
  - RTL regional formats are common with an English UI, so `src/i18n/fmt.rs`
    falls back to numeric dates and times wherever Windows would use an RTL
    script (see "Separate regional formats").
  - With the first RTL locale, once GPUI renders it: turn isolation back on,
    remove that fallback and mirror the layout.
- **Windows changes apply on activation, not instantly.** The pinned GPUI has
  no WM_SETTINGCHANGE bridge, so the display-language list and regional format
  are re-read when the window becomes active. Tests use
  `ATLAS_WINDOWS_LANGUAGES` for recovery paths; release validation must also
  change the real Windows display language.
- **Narrator needs release validation.** The window reports the app's
  language as every node's UI Automation Culture, and each language in
  Settings > Language reports its own (a vendored GPUI patch). UI Automation
  checks don't verify that Narrator speaks a non-English language with the
  matching voice.
- **Thai and Hindi wrapping** relies on a local GPUI patch for ICU dictionary
  line breaks and grapheme boundaries
  ([patch maintenance](../vendor/gpui-pre/ATLAS-PATCH.md)). Other
  dictionary-broken scripts are unverified. The same patch keeps the German
  closing quote `“` and CJK closing and stop punctuation (`。`, `、`, `）`, `」`)
  from starting a row.
- **Release notes** from GitHub stay in the language they were written in.
- **Elevation across users is untested.** The elevated relaunch normally reads
  the launching user's `settings.json` and display-language list. Running it
  as another account with different language settings has not been tested.
